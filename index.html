Rollback is listed in reverse completion order. For an atomic group, all members are treated as one commit unit; if a member fails, the group returns to its previous firmware version. This is a planning demonstration, not a connection to a real vehicle or ECU.

5. Algorithm used

  1. Build a directed dependency graph from the predecessor entries.
  2. Check that the graph is valid and contains no dependency cycle.
  3. Calculate each task's critical-path rank (its duration plus the longest dependent chain).
  4. Start ready tasks in highest-rank order while respecting the maximum number of flash sessions.
  5. Display the schedule, total duration and reverse-order rollback plan.
